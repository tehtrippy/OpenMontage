# H3 Causal A/B — Engineering Record

**Date:** 2026-09-21 · **Project:** `projects/berry-bramble-15s`
**Question:** does a causal scene representation, with and without frame chaining,
fix the object-teleportation failures seen in state-only generation?

> **This experiment validated the WORKFLOW ARCHITECTURE, not the model.**
> It does not establish MiniMax Hailuo-3 as the production model. H3 was the
> vehicle; causal prompting plus frame chaining is the result.

## Setup

| | |
|---|---|
| Model | `minimax/hailuo-3` via OpenRouter |
| Resolution | 2K — 1440x2560 (H3 rejects 720p at validation; 2K is its only tier) |
| Aspect ratio | 9:16 |
| Duration requested | 5s per act |
| Duration observed | **5.167s** on every clip — H3 consistently overshoots |
| Audio | off |
| Acts | A1 place+fill · A2 crush blackberry · A3 add+crush raspberry · A4 add+crush blueberry · A5 serving glass + ice |
| Clips | **10** (5 per arm) |
| Cost | **$6.50** ($0.65/clip, measured from `usage.cost`) |

**Arm A** — causal prompts, no frame chaining.
**Arm B** — identical prompts, `first_frame` = previous act's final frame.
Prompts were byte-identical across arms; chaining was the only variable.

## Results

### Causal prompting fixed within-clip causality — both arms

All five audited defects resolved in A *and* B:

| Audited failure | Outcome |
|---|---|
| empty glass -> fruit added | glass placed empty, hand drops fruit in |
| raspberry enters the glass | second glass tilts in, fruit falls (t≈1.2–2.2s) |
| blackberry + raspberry combination | raspberries land on existing pulp, then crushed |
| blueberry addition | tipped onto existing pulp; no standalone blueberry glass |
| serving glass + ice | empty highball placed, tongs lower ice |

The old state-only prompt produced a glass whose contents changed identity with
no action at all. That mode is gone.

### Frame chaining fixed cross-clip identity — arm B only

Opening frames of the five acts, compared:

- **Arm A** — the working glass changes between every clip: tall narrow, faceted
  pint, shorter wider tumbler, different again, back to tall narrow. Board crop,
  shadow angle and camera height drift with it. Contents jump between clips.
- **Arm B** — the same faceted pint glass in all five. Same facet pattern, board
  grain, shadow and camera height. Contents progress monotonically:
  empty -> whole blackberries -> dark pulp -> red+dark -> bright magenta.

### Residual H3 problems

- Colour-identity drift: by B/A4 the mixture reads uniformly crimson and the
  blueberries' indigo contribution is lost.
- 5.167s instead of 5.000s on every clip.
- 2K forced — ~3x the pixel budget a 1080p timeline needs, at ~5x the per-clip
  price of `google/veo-3.1-lite`.

## API finding

Arm B's first attempt failed **400 (ZodError)** on payload shape, not on the
model. The accepted wire shape is:

```json
{"type": "image_url", "image_url": {"url": "<https or data uri>"}, "frame_type": "first_frame"}
```

The intuitive `{"type": "first_frame", "image_url": "<string>"}` is rejected:
`type` must be the literal `"image_url"`, `image_url` must be an object, and the
first/last selector lives in `frame_type`. Base64 data URIs are accepted.
Failed submits are not charged. This is not in OpenRouter's published docs.

## Conclusions

1. Adopt **causal prompts + frame chaining** together. They fix different
   failures and neither substitutes for the other.
2. The state-only scene representation must not be used for causal generation.
3. **1080x1920 is the production default.** 2K is optional.
4. H3 at $0.65/clip for 2K you then downscale is poor value. `veo-3.1-lite` at
   ~$0.12/clip supports the same `frame_images` conditioning and should be
   evaluated before H3 is adopted for production.
5. Do not repeat exploratory spend at this scale. Plan chains with
   `dry_run=True` and get the total approved first.
